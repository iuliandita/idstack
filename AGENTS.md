# idstack

Infra, DevOps, and SRE playbooks for coding agents, layered on pstack, plus the `idstack` helper CLI
(`bin/idstack`, standard library only). `develop` is the default and nightly branch, `main` is stable.

If `AGENTS.local.md` exists beside this file, read it too. It holds local paths and preferences and never
relaxes the rules here.

## Commands

```sh
python3 scripts/check.py
python3 .github/stack/stack-check.py
python3 -m unittest discover -s tests -v
python3 bin/idstack build --check
ruff check bin/idstack scripts tests
ruff format --check bin/idstack scripts tests
shellcheck install.sh
actionlint
claude plugin validate .
markdownlint-cli2
lychee --config lychee.toml --extensions md *.md agents docs skills src
python3 bin/idstack build
```

The last command regenerates generated files. `markdownlint-cli2` is pinned in
`.github/tools/markdownlint`; `actionlint`, `lychee`, `ruff`, `shellcheck`, and `claude` must be on PATH.
CI also runs gitleaks, zizmor, and an installer run in a throwaway directory; see `.github/workflows/`.

## Layout

- Sources: `agents/*.md`, `skills/`, `src/guard`, `src/questions`, `config/pstack-models.json`.
- Generated by `python3 bin/idstack build`, never hand-edit: `harness/**` and `skills/*/agents/openai.yaml`.
- `.github/stack/` is vendored from the agents repo; `repo.json` is the only file there to edit.
- `.github/tools/harness` pins the harness CLIs CI installs.
- `docs/plan.md` is the design; `docs/playbooks.md` is the playbook catalog. Tests are in `tests/`.
- Installer, update, and recovery details are in [INSTALL.md](INSTALL.md); checks and releases are in
  [CONTRIBUTING.md](CONTRIBUTING.md).

## Rules

- Issue first, branch from `develop`, PR into `develop`, conventional commits, `Closes #NN`. Never commit to `main` or `develop`.
- No AI attribution in commits, PRs, tags, or files.
- No private hosts, domains, IPs, machine paths, or work context in tracked files.
- Keep the three manifest versions and `PSTACK_MIRROR_REF` in `install.sh` consistent.
- Test installer changes only against a throwaway directory with all env overrides set (see CONTRIBUTING.md).
- Answers from Jev only tighten a gate, never loosen it.
- Do not edit `canon.json`, `stack-check.py`, or `SOURCE` under `.github/stack/`.

## For agents

- `python3 bin/idstack check` and `python3 scripts/check.py` are the same repo check; there is no single command that runs
  every check, so run the whole Commands block before pushing.
- Every `idstack` and `install.sh` command accepts `--json`: one object with `ok` and `errors`, human output on stderr.
- Exit codes: 0 done, 1 failed or check found a problem, 2 usage error, 3 a required tool is missing.
  `idstack judge` exits 4 without `TYPESAFE_API_KEY`. The contract is in [INSTALL.md](INSTALL.md).
- `idstack plan-summary PLAN.json --predicate` is the deterministic gate for Terraform and OpenTofu plans.
- `python3 bin/idstack doctor` reports what is installed; `scripts/eval.py` runs headless behavioral evals.
