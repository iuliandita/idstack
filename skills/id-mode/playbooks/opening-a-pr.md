### Opening a PR (idstack overlay)

Read the shared playbook first: pstack `poteto-mode/playbooks/opening-a-pr.md`.

Then apply these gates. They win on conflict.

1. The repo's conventions win over pstack's PR body format: its template, title style, and squash message rules. Without repo rules, pstack's format applies.
2. Conventional commit titles. Reference the tracking issue in the body (`Closes #NN` when the PR completes it). Open the issue first when none exists.
3. No AI attribution anywhere: no co-author trailers, "generated by" lines, or tool names that are not part of the change.
4. Keep squash messages short, and put the why in the body.
5. For a change playbook, the body carries the plan or render summary and says whether merging deploys.
6. Before any push, check the diff, commit messages, and PR text for secrets, and run a secret scanner (`gitleaks git --redact`) when one is installed. Before pushing to a public repo, also check them for private hostnames, internal domains, private IPs, internal URLs, and machine-specific paths. Every candidate blocks the push until the operator or an allowlist clears it.
   Jev decision point (optional): `idstack judge public-hygiene <candidates.json>` ranks the candidates, likely private first. It never clears a candidate.
7. Opening a PR is a reversible write unless the repo builds preview environments or applies on push or PR. Then it is a gate.
